--- ANALYSIS ---
ASan caught nothing, and this is expected: ASan instruments memory
accesses to detect heap/stack/global buffer overflows, use-after-free,
use-after-return, and memory leaks. vulnerable.c never allocates a
buffer or indexes an array - every bug in it is a pure arithmetic/type
conversion defect with no associated memory access violation. ASan is
simply the wrong tool for this class of bug; it would light up
immediately if the program went on to use one of these corrupted
values as, e.g., a memcpy() length or array index that walked off the
end of a buffer, but it cannot see the conversion error itself.
